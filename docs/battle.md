# 네오의 텃밭 대결 — 첫 플레이

[도감](../index.html)에서 **카드 3장으로 텃밭 대결 해보기**를 누르거나
[battle.html](../battle.html)을 엽니다. 완성된 네오 카드로 팀 편성의 재미를 확인하는 데모입니다.

## 로컬 실행

저장소 루트에서 정적 HTTP 서버를 실행합니다. `file://`로 열지 않습니다.

```powershell
py -m http.server 5173
```

`py`가 없다면 설치된 Python으로 실행합니다. 이 개발 PC에서 확인한 명령입니다.

```powershell
python -m http.server 5173 --bind 127.0.0.1
```

대결: <http://127.0.0.1:5173/battle.html> · 도감: <http://127.0.0.1:5173/index.html> ·
스튜디오: <http://127.0.0.1:5173/studio.html>. 이미 같은 포트에 서버가 있으면 중복 실행하지 않습니다.

## 한 판의 흐름

1. 서로 다른 카드 3장을 고릅니다. 선택한 카드를 다시 누르거나 팀의 **해제**를 누르면 빠집니다.
2. **앞 / 뒤** 버튼으로 순서를 정합니다. 1번이 선두이고, 지원으로 오를 공격 수치도 미리 보입니다.
3. **방어 연습 / 지원 연습 / 연타 연습** 중 하나를 고릅니다. 상대의 순서·능력·수치를 확인하고 시작합니다.
4. 두 팀의 맨 앞 살아 있는 카드가 자동으로 맞붙습니다. HP와 능력 메시지를 보고, 필요하면 **대결 기록 보기**를 엽니다.
5. 승리·패배·무승부와 남은 카드를 확인합니다. **같은 팀으로 다시**는 같은 결과를 재현하고,
   **팀 바꿔 도전**은 선택과 상대를 유지한 채 편집으로 돌아갑니다. 대결 중에도 중단하고 편집할 수 있습니다.

## 전투 규칙

공격·체력·능력은 [battle-data.mjs](../battle-data.mjs)의 독립 데이터입니다.
[cards.mjs](../cards.mjs)의 `stat`은 그림의 인쇄 문구, `rarity`는 시각 효과여서 전투에 쓰지 않습니다.
그림과 이름은 기존 원화를 그대로 표시합니다. 이미지의 글자를 바꾸거나 개인화하지 않습니다.

| 카드 ID | 공격 | 체력 | 능력 |
| --- | ---: | ---: | --- |
| `cabbage` | 2 | 7 | 방어 |
| `danhobak` | 1 | 10 | 방어 |
| `lettuce` | 2 | 4 | 지원 |
| `broccoli` | 1 | 7 | 지원 |
| `sweet-potato` | 3 | 5 | 연타 |
| `tomato` | 4 | 3 | 연타 |

- **방어 (`shield`)**: 대결마다 처음 받는 개별 타격 1회를 전부 차단합니다.
- **지원 (`support`)**: 초기 배치에서 바로 뒤 카드의 공격을 시작할 때 한 번 +1 합니다.
  마지막 칸에는 대상이 없습니다. 지원 카드가 쓰러져도 보너스는 유지되고 대상을 다시 고르지 않습니다.
- **연타 (`burst`)**: 자신이 처음 맞붙는 교환에 현재 공격으로 2회 타격합니다. 이후는 1회입니다.
  방어는 이 중 첫 타격만 막습니다.

교환이 시작되면 두 활성 카드의 타격을 먼저 예약합니다. HP가 0이 되어도 예약된 공격은 나갑니다.
모든 타격은 처음 마주한 상대 카드만 겨냥하며, 초과 피해는 다음 카드로 넘어가지 않습니다.
양쪽의 예약 타격이 모두 끝난 뒤 쓰러진 카드를 판정하고, 후속 카드는 다음 교환에 등장합니다.
살아 있는 카드는 HP와 사용한 능력을 유지합니다. 화면 HP는 항상 0 이상입니다.

한 팀만 남으면 그 팀이 승리합니다. 같은 교환에 함께 전멸하면 무승부입니다.
100교환을 넘기려 하면 한도에 의한 무승부를 명시합니다. 같은 ID가 양 팀에 있어도
`player:슬롯` / `opponent:슬롯`으로 상태를 따로 갖습니다. 재도전은 새 상태로 시작합니다.

| 상대 | 선두 → 마지막 |
| --- | --- |
| 방어 연습 | `cabbage` → `danhobak` → `broccoli` |
| 지원 연습 | `lettuce` → `sweet-potato` → `cabbage` |
| 연타 연습 | `tomato` → `sweet-potato` → `lettuce` |

초기 요청 수치를 조정하지 않았습니다. 밸런스 확정값은 아닙니다.

## 구성과 카드 추가

- `battle-data.mjs`: 안정된 카드 ID를 키로 삼은 사용 가능 목록, 공격·체력·능력 ID, 한국어 능력 설명, NPC.
  도감의 이름·원화 경로·원본 크기만 ID로 찾아 가져옵니다.
- `battle-engine.mjs`: `simulateBattle(playerIds, opponentIds)` 순수 함수. 초기화·교환·결과 이벤트와
  각 시점의 상태 사본을 반환합니다. 시간·랜덤·DOM·네트워크·저장을 사용하지 않습니다.
- `battle-ui.mjs`: 데이터 목록을 순회해 선택 화면을 그립니다. 팀 크기는 3이고 카드 풀의 크기는 고정하지 않습니다.
  실제 이벤트의 타격별 HP·방어 여부로 화면과 기록을 갱신합니다. `AbortController`로 이전 재생과 타이머를 취소하며,
  재생 중 중복 시작을 막습니다. 페이지를 떠나거나 뒤로 가기 캐시에서 돌아올 때도 중단된 재생을 정리합니다.
- `battle.css`: 전용 페이지와 `battle-` 이름에만 적용합니다. 원래 도감·스튜디오 CSS와 vendor를 불러오지 않습니다.
  카드를 통째로 움직이며 `prefers-reduced-motion`에서는 이동을 끄고 HP와 피드백은 유지합니다.

기존 능력을 사용하는 새 카드는 `cards.mjs`의 메타데이터·`art/` 원화와
`battle-data.mjs`의 `combatValues` 행만 추가하면 선택 목록과 전투에 들어옵니다.
전투 효과는 채소 이름 대신 능력 ID를 판정합니다. 새 능력은 별도의 전투 로직과 테스트가 필요합니다.
카드 편집기나 플러그인 구조는 없습니다.

## 검증

Node 기본 테스트 러너를 사용합니다. 패키지 설치는 없습니다.

```powershell
node --test tests/battle.test.mjs
node --check battle-data.mjs
node --check battle-engine.mjs
node --check battle-ui.mjs
git diff --check
```

2026-09-08 개발 PC에서 전투 테스트 **12개 통과, 실패/skip 0개**.
방어와 연타, 지원의 원래 대상과 마지막 칸, 사망 이후 예약 타격, 초과 피해,
후속 카드 진입 시 HP/능력 유지, 동시 전멸, 교환 한도, 잘못된 팀,
결정적 이벤트 재현, 양쪽·각 이벤트·반복 대결의 상태 분리를 확인했습니다.

6장에서 순서 있는 3장을 고른 **120팀 × NPC 3종 = 360조합**을 검사했습니다.
각 조합을 한 번 더 실행해 전체 이벤트가 같은지도 비교합니다. 아래 집계는 중복 재실행을 제외한 360조합입니다.
모두 전멸 판정으로 끝났으며 가장 긴 대결은 **23교환**입니다.

| 상대 | 승 | 무 | 패 |
| --- | ---: | ---: | ---: |
| 방어 연습 | 73 | 25 | 22 |
| 지원 연습 | 31 | 33 | 56 |
| 연타 연습 | 50 | 29 | 41 |
| 합계 | 154 | 87 | 119 |

순서의 영향: 연타 연습을 상대로 `cabbage → danhobak → lettuce`는 **패배**,
같은 세 장의 `cabbage → lettuce → danhobak`은 **승리**입니다.
지원이 마지막 칸에서 빠져 단호박의 공격을 올리는 배치입니다.
이 검증은 규칙과 종료 조건 확인이며 재미나 균형의 증명은 아닙니다.

브라우저 검증의 상세 범위와 실제 기기 확인 여부는 [PR #10](https://github.com/SAJOYO/DAENGS_CARDS/pull/10)의
**확인한 것**에 기록합니다. 뷰포트/터치 에뮬레이션은 실제 휴대폰 확인으로 세지 않습니다.

2026-09-08 사용자 플레이 피드백에서 카드 선택·순서 변경의 직관성, 능력과 승패 이유의
이해도, 순서를 바꿔 다시 해 보고 싶은지가 모두 충족됐음을 확인했습니다. 옆에서 본 팀원도
플레이 의향을 보였고, 사용자가 첫 플레이의 main 머지를 승인했습니다. 실물 기기 종류는
확인되지 않았으므로 이 피드백을 실기기 검증 완료로 표시하지 않습니다.

## 이번 범위의 한계

사진 업로드·얼굴 생성·이미지 이름 교체·로그인·소유권·저장·보상·생년월일/오행·레어도 전투력·
멀티플레이·랭킹·앱 연동은 없습니다. 새로고침하면 팀 선택도 초기화됩니다.
대결 중 조작은 중단뿐이고, 드래그·스프라이트·사운드·이머시브 연출은 넣지 않았습니다.
main에 머지되면 GitHub Pages가 도감과 대결 페이지를 함께 배포합니다.
