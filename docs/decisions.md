## CARDS-001
### 도감을 조직 public 저장소 + GitHub Pages 로 분리

도감은 DAENGS 본체와 **코드를 하나도 공유하지 않습니다.** 그런데 Next 저장소의
`frontend/public/` 안에 있었던 탓에, CSS 한 줄을 고쳐도 브랜치 → PR → `dev` 머지 →
self-hosted 러너 배포라는 전체 사이클을 탔습니다. 순수한 비용이었습니다.

**부수효과가 아니라 이게 실질 이득입니다 — HTTPS 가 자이로를 켭니다.**
본체 배포는 nginx `:80` 이라 secure context 가 아니고, 그래서 폰에서
`deviceorientation` 이 **에러도 경고도 없이** 안 켜졌습니다. 자체 서버에 TLS 를 붙이는
것은 되돌리기 번거로운 별도 결정인데, Pages 로 옮기면 **그 결정 없이** 무료 인증서로
얻습니다. 코드는 이미 다 들어가 있어서 주소만 바뀌면 됩니다.

**public 인 것은 선택이 아니라 제약입니다.** `orgs/SAJOYO` 는 plan `free` (seat 7개)
이고, Free 조직은 private · internal 저장소에 Pages 를 못 켭니다. 켜려면 Team 이상
(유저당 월 $4 → 7석이면 월 $28)입니다. 조직의 다른 저장소는 `.github` 을 뺀 전부가
private 이라, **이 저장소만 예외**입니다.

라이선스는 걸림돌이 아니었습니다 — 본체 루트가 이미 MIT (`Copyright (c) 2026 SAJOYO`)
이고 `vendor/cards-css/` 도 MIT 입니다.

이 결정은 한동안 카드에서 **Hold** 였습니다. 기술 문제가 아니라 "도감을 공개해도
되는가" 라는 사람이 정할 문제였기 때문입니다. 2026-08-28 에 저장소를 public 으로
만들면서 해소됐습니다.

**바꾸려면**: 되돌리는 건 저장소를 private 으로 돌리는 것인데, 그 순간 Pages 가 꺼지고
자이로도 같이 죽습니다. 비공개로 가야 한다면 Pages 가 아니라 자체 서버 + TLS 로
돌아가는 결정이 되고, 그건 이 저장소의 존재 이유를 지웁니다.

## CARDS-002
### 이관은 복붙이 아니라 `git subtree split` 으로 히스토리를 살린다

`frontend/public/neo-hologram/` 에는 레어도 연출 · 이머시브 뷰 · 홀로 스튜디오 ·
터치 최적화로 쌓인 커밋이 예닐곱 개 있습니다. 파일만 복사해 오면 그게 통째로 날아가고,
"이 CSS 가 왜 이 값인지" 를 되짚을 방법이 `git log` 가 아니라 사람 기억만 남습니다.
이 폴더는 **실측으로 정한 숫자가 유난히 많은** 코드라 그 손실이 큽니다.

절차는 [migration.md](migration.md) 에 있습니다.

**바꾸려면**: 이관은 한 번뿐이라 되돌릴 일이 없습니다. 다만 **한 번 복붙으로 올려버리면
그 뒤에 히스토리를 되살리는 건 훨씬 번거롭습니다** — 이관 전에 이 문서를 읽는 것이 사실상
유일한 방어입니다.

## CARDS-003
### Pages 는 브랜치 배포로 쓰고 워크플로우를 두지 않는다 — `main` 이 배포 브랜치

Deploy from a branch / `main` / `/ (root)`. **빌드가 없으니 Actions 가 할 일이 없습니다.**
워크플로우를 두면 빌드 산출물이 있는 것처럼 보여서, 다음 사람이 번들러를 넣어도 되는
줄 압니다.

그래서 이 저장소는 **`main` 이 배포 브랜치**가 됩니다. `DAENGS_dev` · `DAENGS_APP` 은
`dev` 가 default 이고 `main` 이 릴리즈 스냅샷이라, **정확히 반대**입니다.
저쪽에서 오는 사람이 반드시 헷갈리는 자리라 `CLAUDE.md` 와 `README.md` 양쪽에 적었습니다.

`dev` 브랜치를 하나 더 두고 `main` 으로 올리는 방식도 됩니다. 지금 안 하는 이유는
저장소에 파일이 41개뿐이고 참여자가 사실상 한 명이라, 중간 브랜치가 배포를 한 단계
늦추기만 하기 때문입니다.

**바꾸려면**: Pages 설정에서 소스 브랜치를 바꾸면 됩니다. `gh-pages` 나 `dev` 로 옮길 때
**`CNAME` 파일이 그 브랜치에도 있어야** 커스텀 도메인이 유지됩니다.

## CARDS-004
### 커스텀 도메인 없이 1단계를 먼저 끝낸다

Pages 는 커스텀 도메인 없이도 `https://sajoyo.github.io/DAENGS_CARDS/` 로 **이미 HTTPS**
입니다. 즉 **이 분리의 실질 이득인 자이로는 1단계에서 이미 켜집니다.** 커스텀 도메인은
그 위에 얹는 이름표이고, 서브도메인 이름이 아직 안 정해졌습니다.

경로가 전부 상대 경로라 서브패스(`/DAENGS_CARDS/`) → 루트(`cards.~/`) 전환에
**재작업이 없습니다.** 그래서 나눠도 손해가 없습니다.

| | 내용 |
| --- | --- |
| **1단계** | 저장소 · 이관 · Pages 켜기 · `.nojekyll` · `index.html` 의 `href="/"` 수정 |
| **2단계** | DNS `CNAME` · 도메인 검증 TXT · `Enforce HTTPS` 확인 |

**다만 나누면 본체의 랜딩 링크(`frontend/app/page.tsx`)를 두 번 고치게 됩니다**
(`sajoyo.github.io/...` → 나중에 새 도메인). 피하려면 1단계에서 링크 교체와
`public/neo-hologram/` 삭제를 **하지 않고** 2단계로 미루면 되는데, 그동안 정본이 잠시
둘이 됩니다.

**어느 쪽을 골라도 링크 교체와 폴더 삭제는 같은 PR 에서** 합니다 — 사이에 404 구간을
만들지 않기 위한 것입니다.

**결과**: 2단계까지 같은 날 끝났습니다. 나누기로 한 판단 자체는 유효했습니다 — 1단계가
떠 있는 동안 서브도메인 이름을 정할 시간이 있었고, 경로가 전부 상대라 전환에 재작업이
**실제로 0건**이었습니다. 예고했던 '링크 두 번 고치기' 비용도 `DAENGS_dev` 카드를 이 뒤로
미루면서 피했습니다. → [CARDS-005](#cards-005)

**바꾸려면**: 2단계 절차는 [deploy.md](deploy.md) 에 있습니다.

## CARDS-005
### 도감 주소를 `cards.weareithero.cloud` 로 (가비아 DNS + GitHub 자동 인증서)

`CARDS-004` 가 남겨 둔 '서브도메인 이름' 을 `cards.` 로 정하고 붙였습니다.

**apex(`weareithero.cloud`)는 선택지가 아니었습니다.** 이미 A `218.145.159.122` 로 자체
서버를 가리키고 있습니다 — `daengs.weareithero.cloud` 와 같은 IP 입니다. apex 로 가려면
그 레코드를 뺏고 GitHub 의 A 4개 + AAAA 4개를 넣어야 하는데, 도메인 본체를 카드 데모가
차지하게 됩니다. `dex.` · `holo.` 도 후보였지만 저장소 이름(`DAENGS_CARDS`)과 맞는 `cards.`
로 했습니다.

**인증서는 사지 않았습니다.** 도메인은 가비아에서 샀지만 SSL 상품은 필요 없습니다 —
GitHub 이 Let's Encrypt 를 자동 발급하고 자동 갱신합니다 (발급 확인: 2026-08-28,
만료 2026-11-26). `.cloud` TLD 도 문제없었습니다.

**네임서버가 가비아라 구성이 단순합니다.** `CNAME` 레코드 한 건(`cards` →
`sajoyo.github.io.`)이 전부입니다. Cloudflare 를 거치지 않으므로 프록시·SSL 모드 문제가
아예 없습니다 — 그 내용은 [deploy.md](deploy.md) 의 '나중에 Cloudflare 로 옮긴다면' 으로
내려 뒀습니다.

전환 후 실측: 리소스 18개 전부 200, `http` → `https` 301, 옛 주소
(`sajoyo.github.io/DAENGS_CARDS/`) → 새 도메인 301. **상대 경로 덕에 서브패스에서 루트로
옮겨오며 고친 코드가 0줄입니다** (`CARDS-004` 가 예측한 그대로).

**바꾸려면**: 커스텀 도메인의 정본은 저장소 루트의 `CNAME` 파일입니다. 이름을 바꾸려면
가비아의 `CNAME` 레코드와 이 파일을 **같이** 고쳐야 하고, `DAENGS_dev` 의 랜딩 링크도
따라옵니다. `CNAME` 파일만 지우면 도메인이 조용히 풀리고 옛 주소로 되돌아갑니다.

## CARDS-006
### 이머시브 배경음을 mp3 로 저장소에 커밋한다

No.01 의 이머시브 뷰에 30초짜리 배경음을 깔았습니다
(`audio/tiptoe-through-clover.mp3`, 705KB · 192kbps CBR · 29.1초).

**음원을 저장소에 넣는 이유**: 빌드가 없는 정적 사이트라 CDN 도 에셋 파이프라인도
없습니다. 이미 `art/` 의 webp 를 그렇게 넣고 있으니 오디오만 다르게 둘 이유가 없습니다.
`art/` 가 아니라 `audio/` 인 것은 `.gitignore` 가 `art-src/` · `*.psd` 로 그 자리를
이미 쓰고 있어서입니다.

⚠️ **이 저장소는 public 입니다**(`CARDS-001`). 음원은 **공개 배포해도 되는 것만**
넣으세요. 그림과 달리 오디오는 출처가 흐려지기 쉽고, Pages 로 서빙되는 순간
누구나 직접 주소로 받을 수 있습니다.

**소리 켜짐이 기본이고, 음소거는 기억하지 않습니다.** 이머시브는 꾹 누르기(520ms)나
★★★ 배지 클릭에서만 열립니다 — 둘 다 사용자 제스처라 브라우저의 자동재생 정책을
통과합니다. 그래서 "들어가면 소리가 난다"를 기본으로 둘 수 있었습니다. 다만
`?im=` 으로 새로고침하는 개발 경로와 iOS 무음 스위치에서는 거부될 수 있고, 그때는
음소거 표시로 두었다가 버튼을 한 번 누르면 살아납니다.

음소거 선택을 `localStorage` 에 남기지 않는 것은, 한 번 끈 사람이 **왜 조용한지 모른 채**
다음에 또 들어오는 상황이 더 나쁘다고 봤기 때문입니다. 열 때마다 소리 켜짐으로
초기화됩니다. 뒤집고 싶으면 `immersive.mjs` 의 `muted` 를 저장소에 붙이면 됩니다.

**루프 이음매는 `<audio loop>` 로 충분했습니다.** mp3 는 인코더 패딩 탓에 되감길 때
수십 ms 의 공백이 생길 수 있어서 크로스페이드(오디오 요소 두 개를 겹치는 것)를 고민했는데,
헤드리스 크롬으로 실제로 재 보니 29.10초에서 0.00초로 **15ms 폴링 해상도 안에서** 넘어갔고
`ended` 도 안 떴습니다. 즉 코드를 더 들일 이유가 없었습니다. 나중에 다른 음원에서
이음매가 들리면 그때 `ensureAudio()` 의 `loop = true` 자리에서 바꾸세요.

**바꾸려면**: 음원 경로는 `cards.mjs` 의 `scene.audio` 한 줄입니다. 그 줄이 없는 카드는
무음으로 돌고 음소거 버튼도 안 생기므로, 다음 이머시브 카드는 줄만 넣으면 따라옵니다.

## CARDS-007
### 도메인 검증은 쓰는 서브도메인만 — apex 는 건드리지 않는다

`cards.weareithero.cloud` 를 조직 도메인으로 검증했습니다
(`protected_domain_state=verified`, 2026-08-28). 검증하지 않으면 우리가 DNS 를 남긴 채
저장소에서 도메인을 떼거나 저장소가 사라졌을 때 **다른 사람이 자기 저장소에 같은 주소를
등록해 가져갈 수 있습니다**(dangling DNS 하이재킹).

**핵심은 apex 를 검증하지 않기로 한 쪽입니다. `weareithero.cloud` 는 여러 팀(여러 org)이
나눠 쓰는 도메인입니다.**

검증 챌린지 레코드 이름에 org 가 박혀 있어(`_github-pages-challenge-SAJOYO`) **여러 org 가
같은 도메인을 각자 검증할 수 있는 구조**이고 레코드끼리 충돌하지 않습니다. 문제는
**apex 검증의 효력이 하위 서브도메인까지 미치는지 확인하지 못했다**는 점입니다. 미친다면
다른 팀이 자기 서브도메인을 자기 org 의 Pages 에 붙일 때 막히고, **우리가 쓰지도 않는
범위를 잠그면서 남에게 조정 비용을 떠넘기는 게 됩니다.**

쓰는 서브도메인을 직접 검증하면 그것이 보호되는 것은 확실하므로, **모호한 상위 검증에
기대지 않습니다.** 반대로 공유 도메인이라는 사실이 서브도메인 검증을 **더** 해야 할
이유이기도 합니다 — 나중에 다른 팀이 apex 를 검증하고 그 효력이 하위까지 미치더라도,
명시적으로 검증해 둔 우리 것은 우리 것으로 남습니다.

실측 (2026-08-28): apex TXT 0건 — 그때까지 아무 org 도 apex 를 검증하지 않았습니다.
우리가 했다면 그 상태를 처음 만드는 쪽이 됐을 것입니다.

**바꾸려면**: 앞으로 SAJOYO 가 이 도메인 밑에 Pages 서브도메인을 더 만들면 **그때마다 그
서브도메인을 각각 검증**합니다. 번거로워 보이지만 공유 도메인에서 남의 몫을 건드리지 않는
유일한 방법입니다. apex 검증이 하위까지 덮는지는 여전히 미확인이고, 다른 팀 중 누군가
apex 를 검증하는 일이 생기면 그때 실측해서 [deploy.md](deploy.md) 에 적으세요.

## CARDS-008
### 카드를 `.spin` · `.tilt` · `.card` 세 겹으로 가르고, 입력은 `.stage` 에 건다

원래는 `.card` 하나가 기울기까지 맡았습니다(`transform: rotateX() rotateY()`).
클릭 회전과 누끼 팝아웃이 붙으면서 셋으로 갈랐습니다.

    .stage   FLIP(확대 뷰로 날아가기) · perspective · 꾹 게이지(::after)
      .spin  720° 회전
        .tilt  포인터 기울기 (--rotate-*)
          .card  그림 · 포일 · 글레어
          .hero  누끼 (팝아웃용, .card 의 형제여야 잘리지 않는다)

**한 요소에 회전과 기울기를 같이 걸면 안 됩니다.** 중첩 3D 회전이 되어 반 바퀴 근처에서
카드가 도는 게 아니라 **비스듬한 바늘**로 넘어갑니다. 데모에서 같은 각도(75°)를 나란히
세워 보고 확인했습니다.

**입력(클릭 · 꾹 누르기)은 `.card` 가 아니라 `.stage` 에 겁니다.** `.card` 는 가만히 있지
않습니다 — 포인터를 따라 최대 ±12° 기울고(3D 투영이라 가장자리의 실제 히트 영역이 눈에
보이는 사각형과 다릅니다), 꾹 누르는 동안 `scale(.955)` 로 5~7px 줄어듭니다. 그래서
가장자리를 누르면 `click` 이 `.card` 가 아니라 조상에서 나서 **그냥 씹힙니다.** 실측으로
잡았습니다 — 카드 오른쪽 끝(97%)에서 `elementFromPoint` 가 `.card` 가 아니라 `.spin` 을
돌려줍니다. "운 좋으면 눌리고 운 나쁘면 안 눌린다" 의 정체가 이것이었습니다.
`.stage` 는 절대 안 움직이고 카드와 같은 상자라, 아무 데나 눌러도 걸립니다.

**바꾸려면**: 겹 이름은 `style.css` 의 `.spin` / `.tilt` 블록과 `main.js` 의 `makeStage`
가 짝입니다. 겹을 하나 더 끼울 일이 생기면 **회전·기울기·FLIP 이 서로 다른 요소에 있는
것만 지키면** 됩니다. 입력을 다시 `.card` 로 내리지 마세요 — 위의 이유가 그대로 돌아옵니다.

## CARDS-009
### 이머시브 진입은 카드 꾹 3초 하나뿐 — 배지는 안내문으로 내린다

카드 한 장에 동작이 셋 붙어 있어서 어디서 무엇이 일어나는지 흐릿했습니다. 이렇게 갈랐습니다.

| 동작 | 결과 |
| --- | --- |
| 카드 **꾹 3초** | 이머시브 |
| 카드 **그냥 클릭** | 상세 정보(확대 뷰) |
| **확대 뷰에서** 카드 클릭 | 720° 회전 |
| 캡션의 `★★★ 꾹 눌러서 들어가기` | 아무 일도 안 함 |

**배지를 `<button>` 에서 `<span>` 으로 내렸습니다.** 버튼이던 시절에는 눌러서도 들어갈 수
있었는데, 그러면 카드를 안 누르고 배지만 누르게 됩니다. 들어가는 길을 하나로 만들었습니다.

⚠️ **그 대가로 키보드 · 스크린리더에서 이머시브로 들어갈 길이 없어졌습니다.** 배지가
유일한 그 경로였습니다(`CARDS-006` 도 배지를 진입로로 전제하고 쓰여 있습니다). 이건
접근성 후퇴이고, 그 사실을 알고 내린 결정입니다.

**꾹 시간은 3초입니다.** 처음 520ms 였는데 실제로 누르는 사람이 231ms 에 손을 뗐습니다 —
움직임 없이(`d=0`) 게이지만 절반쯤 차다 사라져서 "카드가 안 눌린다" 로 보였습니다. 그래서
220ms 까지 내렸다가, 명세로 3초를 잡으면서 되돌렸습니다. **3초를 요구하는 이상 게이지가
확실히 보여야 합니다** — 링 두께를 5px 로 키우고 카드가 눌려 들어가게 했으며,
`prefers-reduced-motion` 에서 게이지 애니메이션을 끄던 규칙도 없앴습니다(진행 표시는
장식이 아닙니다).

**바꾸려면**: 시간은 `immersive.mjs` 의 `HOLD_MS`, 게이지는 `immersive.css` 의
`.stage.is-holding` 블록입니다. 키보드 경로를 되살리려면 배지를 다시 `<button>` 으로
올리되 **클릭은 막고 `Enter`/`Space` 에서만 열리게** 하는 절충이 있습니다.
